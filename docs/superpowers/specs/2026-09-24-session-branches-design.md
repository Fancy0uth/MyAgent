# L18 会话树与分支设计

**状态：** 对话设计已确认；等待用户审阅本文件。尚未实现。

**日期：** 2026-09-24

## 目标

将现有追加式 JSONL 会话从线性父子链扩展为可分支的记录树，让使用者能查看聊天树、切换活动聊天节点，并让 Agent 只携带当前分支的聊天历史继续运行。已有 L16/L17 记录仍可加载；分支切换不撤销工作区文件修改，也不绕过 L17 的写入恢复安全检查。

## 范围

- 修改 `sessions.py`，以 `id → entry` 索引和 `parent_id` 表示树，保留追加式 JSONL 文件。
- 修改 `agent.py`，使 `run_agent` 使用活动分支的消息；使 `recover_agent` 只从活动路径恢复对话，同时仍对全日志检查写入操作。
- 新增 `tests/test_branches.py`，并按需要扩展现有会话/恢复测试。
- 更新 `mds/PROGRESS.md`，分开记录代码实现、实际测试证据和学习者理解状态。

不在本课范围：复制成新会话、回滚工作区文件、自动切换 Git 分支或快照、改变工具权限、调用真实模型、修改 L17 写入批准规则。

## 记录结构与兼容性

每行继续保留当前字段：`schema_version`、`id`、`parent_id`、`timestamp`、`type`、`payload`。每条记录仍是不可变的追加记录；`parent_id` 可指向任意一条更早写入的记录，而不再要求它必须是物理上一行记录。首次记录的 `parent_id` 为 `null`。现有线性文件满足这一规则，因此无需重写历史或改变现有 schema 版本。

所有记录（聊天、运行状态、工具调用、操作账本和分支选择）都有唯一 ID 并属于同一父子图。省略 `append` 的 `parent_id` 时，记录接到活动叶子；显式指定父 ID 时，从该已存在节点建立新子节点。两个子节点可以拥有相同父节点。添加 `branch_selection` 记录来持久化导航选择；该记录的父节点是所选聊天节点，选择记录本身成为新的活动叶子。它只用于导航，不能作为聊天消息传给模型。

默认可选为活动节点的类型是 `user_message`、`assistant_message` 和 `tool_result`。运行状态、工具调用日志、运行上下文、操作意图/批准/结果以及分支选择记录不能作为用户选择的聊天锚点。选择不存在的 ID 或不可选择类型必须明确失败，不得回退到最新历史。

加载完整文件时，验证记录字段和类型、ID 唯一性、父节点存在、父节点在追加顺序上早于子节点，以及整张图无环。循环检查先于“父节点必须更早”的检查，以便损坏文件中的循环得到明确的 `CYCLE_DETECTED` 错误，而不是被模糊归类为父节点顺序错误。缺失父节点返回 `ORPHAN_PARENT`；非法活动节点返回 `INVALID_BRANCH_TARGET`。具体错误消息不属于外部稳定接口。

## 活动路径与模型上下文

`SessionStore` 提供以下使用方式：

- `get_active_path()`：从活动叶子沿 `parent_id` 回溯到根，返回根到叶子的记录列表。
- `get_model_history()`：从活动路径按原顺序筛选 `user_message`、`assistant_message` 和 `tool_result` 中的模型消息；保留工具协议需要的 `tool_call_id` 和助手工具调用字段；排除 `run_context`、`run_status`、操作账本及分支导航记录。
- `select_active_node(node_id)`：验证节点类型后追加持久化的 `branch_selection` 记录，并将活动路径切换到该历史位置。
- `render_tree()`：输出便于终端阅读的简洁聊天树，隐藏纯运行/操作元数据，但保留每个聊天分支的父子关系。

`run_agent` 在记录本轮 `run_context` 和用户消息之前，先取得活动分支的消息副本，再把新用户问题接在副本之后交给 Provider。因此兄弟分支内容不会进入 `respond(history)`。不传 `session_store` 时，现有单次运行行为保持不变。`run_coding_flow` 继续使用其既有的单任务上下文；它的追加记录遵从 SessionStore 活动父节点，但本课不把它改造成跨任务聊天界面。

## 恢复与副作用安全

`recover_agent` 用活动路径确定当前分支的消息、工具调用、工具结果和运行状态；不能按 JSONL 物理顺序切片并把兄弟分支拼入历史。若导航到旧节点后尚无新的活动运行，恢复不得把被分支选择越过的旧运行误报为当前中断运行，也不得因活动节点选择而自动重放非只读工具。

写入操作的 `operation_intent`、`operation_approval` 和 `operation_result` 账本仍从完整 JSONL 文件检查，而非只检查当前聊天分支。这样切换聊天上下文不能隐藏其他分支已经发生、结果未知或需要核对的工作区副作用。现有工作区、权限配置、哈希和用户确认检查保持不变。

## 测试与验收

所有模型相关测试使用现有 Mock/fake 客户端，不进行网络调用。测试至少覆盖：

1. 原有线性 JSONL 会话仍可加载，新记录默认接到活动叶子。
2. 从同一用户消息建立 A/B 两个后续分支，重新打开 SessionStore 后仍能选择任一分支。
3. `get_active_path()` 与 `get_model_history()` 只含所选节点的祖先，不含兄弟分支私有消息。
4. `run_agent` 发送给 Mock Provider 的历史包含活动分支 A 的消息，但不含 B 的私有消息；工具调用及工具结果协议字段仍完整。
5. 树形文本展示分支结构，并隐藏非聊天记录。
6. 加载时拒绝孤儿父节点和循环引用；选择不存在的 ID 或错误类型明确失败。
7. `recover_agent` 的当前消息历史遵循活动路径；另一个分支中的未知/待核对写入操作仍会进入全局操作账本检查。
8. 现有会话、恢复、编码流程与 Agent 测试继续通过。

实现按测试先行：每个新行为先写测试并确认因缺少功能而失败，再写最小实现，最后运行相关测试与整个标准库 `unittest` 套件。报告准确的运行数量和失败/跳过情况；不以 Mock 测试声称真实模型验证通过。

## 关键限制

- 会话分支只改变聊天上下文，不是工作区快照。
- 不自动执行 `git reset --hard`，不覆盖或清理用户未提交文件。
- 不新增依赖，不调用真实模型，不访问 `ev-ai-assistant`。
- 不提交 Git；提交需要用户另行明确授权。
