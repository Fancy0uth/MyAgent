# L26—L30 学习路线完成 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task. 本计划按用户已选择的 Native 方式执行；每个任务都必须先写失败测试，再实现，再回归。

**Goal:** 在不重写现有 Agent 核心的前提下，完成学习版 JSONL/RPC、固定 Pi 版本原生对照、原生扩展、能力差分矩阵和可重复交付文档。

**Architecture:** CLI、TUI 和 RPC 都调用现有 `run_agent()`，通过 `EventRecorder` 接收事件，不复制模型/工具循环。Pi v0.85.1 放在 MyAgent 外部的独立 checkout；Python 学习实现、原生 TypeScript 练习和兼容性评测使用不同目录与会话文件。

**Tech Stack:** Python 3.13 标准库 `unittest`、JSONL、线程与 `threading.Event`；Pi v0.85.1 的 Node/npm/TypeScript 工具链；现有 Mock Provider，真实 DeepSeek 只做明确的最小验证。

**Spec:** `docs/superpowers/specs/2026-10-04-l26-l30-completion-design.md`

## Global Constraints

- RPC stdout 只输出一行一个 JSON 对象；调试信息不能写入 stdout。
- RPC 输入按 `b"\\n"` 分隔，不使用 `splitlines()` 拆协议。
- RPC 请求命令只有 `prompt`、`get_state`、`abort`；协议不声明兼容 Pi 原生 RPC。
- RPC `prompt` 忙碌时拒绝，不排队第二个任务；`abort` 使用协作式 `cancel_event`。
- L27/L28 固定 Pi `v0.85.1`，不修改 Pi checkout 内核，不让未知扩展自动加载。
- 不把真实 API Key 写入代码、日志、测试夹具或 Git。
- 不自动提交、推送、部署或访问 `ev-ai-assistant`。
- 每个新行为必须先有失败测试或可复现失败证据；所有 Python 代码使用现有 `unittest` 风格。

## Review Focus

- 包含 U+2028、中文和嵌入换行的 JSONL 请求必须保持一条记录；由 Task 1 的协议测试固定。
- RPC EOF、空行、损坏 UTF-8、损坏 JSON 和未知命令必须产生错误消息而不是让服务器崩溃；由 Task 1 测试固定。
- 运行中收到 `abort` 时必须先收到 `accepted`，最终收到 `cancelled`，且不开始下一次模型/工具调用；由 Task 2 集成测试固定。
- 会话路径、扩展路径或兼容性夹具失败时必须清楚标记阻塞，不得写成“Pi 原生测试通过”；由 Task 3/4/5 文档和测试固定。
- L30 的真实评测记录不得包含凭据，且必须区分 Mock、真实调用和未运行；由 Task 6 评测日志测试固定。

### Task 2: L26 异步 RPC Server、取消和最小 Python Client

**Files:**
- Modify: `rpc.py`
- Create: `rpc_client.py`
- Modify: `events.py` only if the existing event payload needs a non-breaking serialization helper
- Test: `tests/test_rpc.py`

**Interfaces:**
- `RpcServer(run_fn=run_agent, run_kwargs=None) -> None`
- `RpcServer.handle_request(request: dict) -> list[dict]`
- `RpcServer.poll() -> list[dict]`
- `RpcServer.serve(input_stream, output_stream) -> None`
- `RpcClient(server).request(message: dict) -> list[dict]`

- [ ] **Step 1: Write failing server/client tests**

  Add a fake blocking `run_fn` that accepts `event_recorder` and `cancel_event`. Assert `prompt` returns `accepted` before completion, event/result messages keep the original `request_id`, `get_state` reports idle/running state, `abort` produces a final cancelled result, duplicate prompt returns `BUSY`, and EOF drains pending output.

- [ ] **Step 2: Run the new integration tests and verify failure**

  Run: `python -m unittest tests.test_rpc -v`
  Expected: failures for missing `RpcServer`, `RpcClient`, or asynchronous behavior.

- [ ] **Step 3: Implement the server with one serialized output path**

  Start one worker thread per accepted prompt, store one active request and `threading.Event`, subscribe the request recorder to fixed events, and append all `accepted/event/result/error` messages to a locked output queue. Reject a second prompt while active. `abort` sets the event and never calls a second model request.

- [ ] **Step 4: Implement `RpcClient` as a thin protocol caller**

  `RpcClient` must only encode a request, call the injected server/stream, decode responses, and return them; it must not call tools or `run_agent()` directly.

- [ ] **Step 5: Run L26 tests and a Mock pipe smoke test**

  Run: `python -m unittest tests.test_rpc -v` and a subprocess/BytesIO test with a Chinese prompt and `/`-like text. Expected: accepted → event(s) → result, all stdout records valid JSONL.
