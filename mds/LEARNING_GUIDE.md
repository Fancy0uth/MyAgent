### 0.4 统一的工具契约：不要再回查旧 AGENTS

这些是**学习版设计**，不是 Pi 或任何模型服务的原生格式。已有代码可以先保留实现，通过小步修改符合契约，不能为了改名整仓重写。

```text
list_files() -> dict
read_file(path: str, start_line: int = 1, end_line: int = 80) -> dict
search_text(query: str) -> dict
dispatch_tool(call: dict) -> dict    # L04 才增加
```

**路径和资料。**由程序根据 `tools.py` 所在位置定位 `sample_repo`；模型不能选择根目录。初始允许清单只包含 `README.md`；三个工具共享它。只处理人工准备的少量 UTF-8 普通文件。拒绝绝对路径、上级跳转、符号链接及 Windows 重解析路径，不访问凭据、主目录或其他项目。路径规范化之后仍需检查范围，字符串前缀判断不是安全边界。[S21]

**文件列表。**只返回允许清单内确实存在的普通文件，按相对路径排序；不先扫描整个磁盘再过滤。

**读取范围。**行号从 1 开始，包含结束行；结束超过文件末尾时截到实际末尾。空文件成功返回空内容，实际起止行均为 `null`；非空文件起始行超过末尾报 `INVALID_RANGE`。布尔值不能当整数行号；零、负数、倒置范围或错误类型均拒绝。每行标记真实原文件行号，不能对片段重新从 1 编号。

**关键词搜索。**先做区分大小写的字面搜索，不支持正则；拒绝空白关键词，一行算一个匹配。没有命中返回成功的空列表；允许文件读取失败返回 `READ_ERROR`，不要把漏扫伪装成无匹配。

**初始练习上限。**单文件最多 256 KiB；一次读取最多 80 行；一次搜索最多 50 个命中；单次工具结果经 `json.dumps(..., ensure_ascii=False)` 序列化后最多 12,000 个字符。它们是本项目的练习配置，不是行业标准。超大文件不读取全部内容后才检查；结果过大在结构内部裁剪文本/条目，保持合法 JSON 并标 `truncated: true`。一条很长的行也受限制，行号不能因此造假。

读取成功示例：

```json
{"ok":true,"path":"README.md","start_line":1,"end_line":2,"content":"1: 项目名称：Mini Tasks\n2: 用途：记录学习任务","truncated":false}
```

空文件示例：

```json
{"ok":true,"path":"README.md","start_line":null,"end_line":null,"content":"","truncated":false}
```

列表、搜索、失败示例：

```json
{"ok":true,"files":["README.md"],"truncated":false}
```

```json
{"ok":true,"matches":[{"path":"README.md","line":3,"text":"任务数据保存在本地 SQLite 数据库。"}],"truncated":false}
```

```json
{"ok":false,"error":"FILE_NOT_FOUND","message":"允许范围内的目标文件不存在"}
```

错误码统一为 `INVALID_ARGUMENT`、`INVALID_RANGE`、`ACCESS_DENIED`、`FILE_NOT_FOUND`、`FILE_TOO_LARGE`、`READ_ERROR`、`UNKNOWN_TOOL`。工具函数返回数据；打印由入口负责，不靠 `print` 代替 `return`。

L04 的分发器接收 `id/name/arguments`。处理成功或可关联的失败都返回同一 `tool_call_id`，例如：

```json
{"tool_call_id":"call-1","result":{"ok":true,"files":["README.md"],"truncated":false}}
```

`id` 缺失等无法关联的请求直接报协议/参数错误，不发明 ID 后假装收到合法请求。不使用 `eval`、`exec` 或模型指定的任意动态导入。

<a id="runtime-contract"></a>
### 0.5 一份消息协议和停止状态

L05 的学习接口是 `complete(messages, tool_specs) -> ModelReply`，先用字典理解即可。`ModelReply` 至少有 `text/tool_calls/stop_reason`；适配器保留所选 API 必需的原始协议项。SDK 适配放在 `model_client.py`，不要把服务商响应对象传到文件工具里。

必须先保存完整助手响应，再处理工具调用，再保存关联结果，然后才发下一次模型请求。多个调用先串行；各自有结果。未执行的调用不能假报成功，预算不足不能带着缺结果的历史继续请求模型。

| 数据 | 合并版唯一约定 |
| --- | --- |
| 普通运行状态 `status` | `completed / failed / stopped / cancelled` |
| 写入与恢复阶段新增 | `waiting_confirmation / recovery_required` |
| 原因 `reason` | 明确区分预算、超时、协议错误等；如 `model_call_limit`、`tool_call_limit` |
| 验收 `validation` | `not_run / unverified / passed / failed`，独立于运行状态 |
| 模型归一停止原因 | `final / tool_calls / length / error`，必要时再显式增加，不等同于厂商全集 |

旧六关里的 `stopped_limit` 在合并版中映射为 `status=stopped` 加对应 `reason`。若你的实现已经使用旧名字，先说明映射并做受影响测试，再小步改动；不能同时在不同模块随意使用两种写法。

初始预算：最多 5 次模型请求、10 次工具执行。运行总时限先显式配置为 120 秒作为练习起点；单次请求超时不能超过剩余总时限。每次调用**之前**检查预算。终止后不额外送一次不计数的模型“收尾”。默认关闭 SDK 隐藏重试；今后启用时把真实尝试计入记录。并行、流式和多会话后面再做。

`completed` 只是得到正常最终响应；答案正确或补丁通过测试，必须另有验收证据。没有用量信息就记未知，不填零；不把本地取消说成远端计费已停止。

### 0.7 本地核心的复用边界与阶段出口

本节描述 L02 的拆分方式，不代表每次接手都从 L02 开始。若当前代码已经覆盖工具、分发、循环或真实适配，应先核对代码和证据，直接进入第一个真实缺口；不要为了符合教程排列而重做已完成能力。

### 1.2 Codex 在这里是助教，不是代写整个项目的工程队

默认一次只处理一课中的一个小步骤。用户问“为什么 / 怎么写”时，先解释并提示，不自动重写文件。用户明确要求示范或修改时，只实施当前步骤，说明输入、输出、执行时机和验证方法。

每次教学回复最好包含：本次小目标、要看的文件、一个概念、一个操作、预期现象、失败排查和一个理解问题。不使用“你应该已经懂了”跳过说明。

允许使用标准库、官方模型 SDK、可靠的校验与终端库。学习者重点亲手完成控制流、工具分发、状态转换与验收条件；不要求自行实现 HTTP/TLS、完整 JSON 解析器或终端驱动。

本文与同包的 `AGENTS.md` 共同构成同一个项目的学习说明；不覆盖 Codex 自身权限、系统指令或其他适用规则。旧版“当前六关不开放写入和命令”的约定在本合并版中转为阶段门槛：A/B 阶段只读；C 阶段才可在对应能力验收、用户授权及隔离条件满足后逐项开放。教程不是自动执行授权，也不靠修改文档替代程序权限检查。

### 1.3 教学中使用的词

| 词 | 在本项目中的意思 |
| --- | --- |
| Provider / 模型适配器 | 把自己的请求结构转换成一家模型服务的 API，再转换回统一结果 |
| Tool / 工具 | 程序允许模型申请调用的一个具体函数 |
| Dispatcher / 分发器 | 检查名称与参数，然后选择对应工具函数 |
| Agent loop / 执行循环 | 模型返回行动，程序执行并反馈，再继续或停止 |
| Session / 会话 | 可恢复的一段交互历史及其关联状态 |
| Event / 事件 | 某件可观察的事发生了，例如工具开始、结束或失败 |
| Harness / 运行支持系统 | 模型外部的工具、环境、状态、上下文、交互和验证机制 |
| Compaction / 上下文压缩 | 保留完整记录，减少下一次实际发送给模型的信息 |
| TUI | 在终端中展示可交互界面，不等于网页 |
| RPC | 一个进程通过规定的消息格式请求另一个进程完成操作 |

## 四、阶段 A：先做本地可控核心

<a id="l01"></a>
### L01 · 确认入口真的执行了

**目标：**解决“运行的究竟是什么、为什么没有输出”，不猜故障原因。

**只看：**实际存在的 `main.py`、`tools.py`、`sample_repo/README.md`。先不读 Pi。

**操作顺序：**

1. 在编辑器中打开当前项目根目录，保存文件。终端执行 `python --version`；环境命令是 `python3` 时统一替换后续命令，不为名称重装环境。
2. 执行 `python main.py`，保留完整输出，包括错误和退出状态。
3. 检查是否有函数调用入口，调用是否打印返回值，README 是否为空；必要时临时在入口打印 `__file__`。
4. 若 `tools.py` 中已经有约定接口，让 `main.py` 只调用一次 `read_file("README.md", 1, 3)`，不要导入尚未写出的工具。
5. 修改一行练习 README，再运行；应看到内容变化。临时改名 README，再观察并恢复文件名。

**可用的最小入口示例（仅在已有对应函数时）：**

```python
from tools import read_file


def main() -> None:
    print("main.py 已启动")
    print(read_file("README.md", start_line=1, end_line=3))


if __name__ == "__main__":
    main()
```

**过关证据：**实际文件路径、一次正常输出、一次文件缺失的明确错误。函数只返回却不打印，可能看不到终端内容；这是一条排查方向，不是未经检查的结论。

**理解问题：**`def`、导入、调用、`return`、`print` 分别在哪个时刻发生？

<a id="l02"></a>
### L02 · 只实现一个可靠的 read_file

**目标：**让文件读取成为有输入、输出和边界的函数。[S4][S21]

**文件：**修改 `tools.py`；新增 `tests/test_tools.py`，用临时目录或测试注入配置，不改用户真实文件。

**操作顺序：**

1. 固定资料根目录与允许清单，第一版只允许 `README.md`。路径不是模型决定的根目录。
2. 明确行号从 1 开始，包含结束行；空文件成功返回空内容与空范围，起始行超过非空文件末尾返回范围错误。
3. 成功结果返回 `ok/path/start_line/end_line/content/truncated`；失败返回 `ok/error/message`，不返回敏感绝对路径。
4. 先实现读取，再增加真实行号，最后增加类型、范围与文件大小检查。
5. 自动测试正常读取、越界行号、空文件、不存在文件、布尔值行号、不允许路径。布尔值不能当整数行号接受。

**最初的测试设计例子：**测试夹具写三行 `a\nb\nc\n`；读取第 2—3 行，应包含 `2: b`、`3: c`，不包含 `1: a`。结果不要由“正确实现的另一个副本”生成，直接使用人工明确的预期。

```bash
python -m unittest discover -s tests -p "test_tools.py" -v
```

**必须制造的失败：**`../outside.txt`、绝对路径和符号链接指向外部。初期直接拒绝符号链接和 Windows junction 等重解析路径；不只检查字符串前缀。路径规范化和文件允许清单不是完整安全沙箱，更不能保护并发恶意修改场景。

**过关：**只读、行号正确、错误可解释，自己能添加一个边界测试。

<a id="l03"></a>
### L03 · 加文件列表和关键词搜索

**目标：**完成三个可以手动调用的工具，不调用模型。

**文件：**`tools.py`、`main.py`、`tests/test_tools.py`。

**操作顺序：**

1. `list_files()` 从同一允许清单筛选存在的普通文件，按相对路径排序；不能先扫描整个主目录再过滤输出。
2. 在测试夹具中增加由人写的 `config.py`，明确扩充允许清单。不要打开整个主产品仓库。
3. `search_text(query)` 先做区分大小写的字面搜索，一条匹配对应一行；拒绝空白关键词，不引入正则或向量数据库。
4. 一次最多返回约定数量的匹配，长行和大输出需要截断标记。未匹配是成功的空列表，不是异常。
5. 在 `main.py` 逐个调用并打印；再测试隐藏文件、凭据文件和不允许文件没有通过搜索泄露内容。

**验收：**手动得到文件列表、指定片段和搜索位置；三个工具共享同一访问边界。只有文件名列表正确、读取仍可越权，不算通过。

**理解问题：**为什么这仍然不是 Agent？答案应包括“目前是人/固定代码决定调用顺序”。

<a id="l04"></a>
### L04 · 根据调用数据分发工具

**目标：**把结构化请求变成受控函数调用。

**文件：**在 `tools.py` 增加 `dispatch_tool(call: dict) -> dict`，在 `main.py` 手动调用；新增 `tests/test_dispatch.py`，不急着创建复杂注册系统。

输入样例（学习版协议，不是直接发给任意模型 API 的格式）：

```json
{"id":"call-1","name":"read_file","arguments":{"path":"README.md","start_line":1,"end_line":3}}
```

**操作顺序：**

1. 检查顶层结构、非空调用 ID、工具名称与参数对象。
2. 明确映射名字到函数；可以先写三个分支，之后再整理成注册表。
3. 每个工具检查必填项、类型、范围与未知字段，不把未校验参数直接 `**kwargs` 注入函数。
4. 返回包含同一 `tool_call_id` 的结果。未知工具和非法参数要返回可处理错误。
5. 给真实工具加测试计数器，证明非法参数时工具根本没执行。

```bash
python -m unittest discover -s tests -p "test_dispatch.py" -v
```

**过关：**相同输入选择正确函数；`eval()`、`exec()`、任意导入均不作为分发方案。

**理解问题：**工具的“说明书”和“执行代码”分别在哪里？

<a id="l05"></a>
### L05 · 写一个能检查历史的模拟 Provider

**目标：**先把模型依赖变成可控接口。

**文件：**新增 `model_client.py`、`agent_types.py`、`tests/test_model_client.py`。

**学习版接口：**`complete(messages, tool_specs) -> ModelReply`。第一版用字典，理解后再使用 dataclass / 类型标注；不要为了类型系统跳过可运行逻辑。

`ModelReply` 至少包含：`text`、`tool_calls`、`stop_reason`。停止原因归一成 `final`、`tool_calls`、`length`、`error`；不把这个列表声称为全部厂商原生枚举。

**操作顺序：**

1. 第一次模拟返回 `list_files` 调用。
2. 第二次先断言历史中已有对应工具结果，再返回 `read_file` 调用。
3. 第三次先断言读取结果实际存在，再返回预设最终文本。
4. 增加“永远申请工具”“返回未知工具”“报错”“同时两个工具调用”四个脚本场景。
5. 所有模拟输出明确标注 Mock；模拟实现不根据 Key 是否存在偷偷切换真实 API。

**验收：**忘记加入历史时模拟器主动失败，不能只按计数顺序给答案、把损坏流程也测通过。

```bash
python -m unittest discover -s tests -p "test_model_client.py" -v
```

**理解问题：**模拟 Provider 验证的是程序机制，还是模型真实能力？

<a id="l06"></a>
### L06 · 亲手写第一个 Agent loop

**目标：**串起模型、分发器、历史和结束状态。[S5][S6]

**文件：**新增 `agent.py`；修改 `main.py` 以显式模拟模式运行；新增 `tests/test_agent.py`。

**操作顺序：**

1. 保存用户请求，调用 Provider；不要一开始做流式和多线程。
2. 将完整助手响应加入历史，再处理它的工具调用；每个工具结果必须关联正确 ID。
3. 一次返回多个调用时先串行执行，全部补齐结果，不只执行第一个。
4. 有工具结果则继续请求模型；没有调用且有合格最终文本才正常结束。空响应和格式错误不等于成功。
5. 调用前检查模型调用总数、工具总数、总时限和取消标记；达到预算记为 `stopped`。
6. `length` 截断、Provider 错误或取消时，不能执行可能不完整的工具参数；明确失败/停止，不能无限重试。
7. 默认只允许一次运行；不需要立刻支持并行多个会话。

```text
用户输入 → Provider → 完整助手消息 → 分发工具 → 带 ID 的结果 → 下一轮
```

```bash
python -m unittest discover -s tests -p "test_agent.py" -v
python main.py
```

**故障练习：**删除一次历史追加、互换两个 call ID、让模拟器永不结束。三个测试分别应失败或在预算处停止。

**阶段 A 过关：**你能不照抄完整答案，解释并修改每一步；目前只是离线机制验证，不宣称真实模型已会解题。

Windows 可使用 `npm.cmd` 避开 PowerShell 对 `npm.ps1` 的运行限制，不需要全局降低执行策略。全局已经有 Pi 时，不能只凭 `pi --version` 就认定运行的是这个固定版本。

**独立配置（先进入一个由你创建的干净观察目录）：**

Windows PowerShell：

```powershell
$env:PI_CODING_AGENT_DIR = Join-Path $PWD ".pi-observation"
$env:PI_OFFLINE = "1"
```

Mac/Linux：

```bash
export PI_CODING_AGENT_DIR="$PWD/.pi-observation"
export PI_OFFLINE=1
```

`PI_OFFLINE` 在此基线是关闭启动阶段的网络活动，不是禁止模型请求的网络沙箱。独立配置目录也不是文件权限边界。[S7]

**授权真实观察时的参数约束：**显式选择 Provider/模型；仅启用 `read,grep,find,ls`，关闭扩展、Skills、模板和上下文文件自动发现；不运行在家目录或主项目目录中。现成配置/插件可能执行代码，不能只靠“我只问了一个只读问题”保证安全。

不要直接照抄旧笔记中的权限相关 CLI 参数。先用固定版本的 `--help` 核对“启用哪些只读工具、禁用自动资源发现、独立配置与会话”的参数，再写入本机观察命令。不要为了消除提示而关闭安全审批；命令行参数不是文件系统沙箱。

未核对可用参数前仅阅读源码或运行 `--version` / `--help`，不提交真实任务。不自动登录，不假设订阅等于通用 API 凭据。

**过关：**你能画出模型层、循环层、工具层、会话层、界面层的调用关系。原版未成功安装时仍可继续阅读和 Python 练习，不把安装失败误认为无法学习循环。

### L08 · 只接一家真实模型服务

**目标：**替换 Provider，不重写工具和循环。[S8]

**文件：**`model_client.py`、相关测试、只记录配置名的 `.env.example`；真实 `.env` 和凭据不提交。

2. 单工具往返：只暴露 `read_file`，观察原始工具名称、参数与 call ID，真实执行后正确返回。
3. 多工具循环：接入第 06 课，使用同一套工具和上限，完成搜索 → 阅读 → 回答。

**过关：**留有脱敏轨迹；无凭据/未开启真实模式时没有外部模型调用。模型能回答一个常识问题，不代替读取证据的验收。

### L09 · 事件、取消与最小观察面板

<a id="l10"></a>
### L10 · 先准备缺陷样例、独立验收与隔离边界

**目标：**先知道“修好”的含义，再给 Agent 写代码和执行代码的能力。

**文件：**新增 `fixtures/mean_case/`、该样例的验收测试、`workspaces/` 与 `policy.py`。正式主项目不参与。

使用一个由人准备的小缺陷，足够让你理解闭环，不是用陌生真实仓库测试安全边界。示例 `buggy_stats.py`：

```python
def mean(values):
    if not values:
        raise ValueError("values must not be empty")
    return sum(values) / (len(values) + 1)
```

**人工确认的验收：**

| 输入 | 期望 |
| --- | --- |
| `[2, 4, 6]` | `4.0` |
| `[5]` | `5.0` |
| `[-2, 2]` | `0.0` |
| `[]` | 抛出 `ValueError` |

**操作顺序：**

1. 保留一份干净原始夹具，记录哈希；每次运行复制到新的 `workspaces/<run_id>/`，不在原始夹具上修复。
2. 写独立测试，先运行当前人为代码确认确实有失败。测试是题目规格，不由模型重写。
3. 将可编辑代码与受保护的验收代码分开；测试输入和断言由人检查。少量公开测试用于反馈，另外保留独立验收案例。
4. 在 `policy.py` 中定义只读与可写范围，允许写入的只有本次实验副本。
5. 准备并检查隔离执行环境。尚未有隔离环境时，后续可以继续生成补丁草稿，但不能在宿主机执行模型修改过的代码。

**隔离检查不是一句“只改这个目录”：**工具进程不能拿到宿主机 API Key、SSH 目录、主项目或 Docker socket；不使用 `--privileged`、host 网络或挂载整个家目录。[S20][S30]

**过关：**人工代码的已知失败能重复出现；原件与验收测试受到保护；一份 `policy` 明确写出允许操作。这里有意没有把普通命令白名单称为沙箱。

### L11 · 先做可预览的 write，而不是直接覆盖

**目标：**学习“申请写入、检查、确认、保存、核实”。[S9]

**文件：**`policy.py`、`agent_tools/write.py`、`main.py`、`tests/test_write.py`。拆包时保留旧工具入口兼容，先测试再移动。

**建议接口：**`propose_write(path, content)` 生成提议；`apply_proposal(proposal_id)` 是程序受控操作，不由模型自行声明已批准。

**操作顺序：**

1. 最初只允许写实验副本内的一个普通文本文件；不写项目配置、凭据、入口脚本或验收测试。
2. 检查内容类型、编码、路径、大小；已有文件保存旧哈希，新建文件记录“原先不存在”。
3. 生成提议 ID，展示新旧差异。用户确认必须绑定具体内容/路径/旧哈希，不能只保存全局 `approved=true`。
4. 执行前再检查旧文件未变化；变化了就返回冲突并重新审核。先写临时文件，再在同一文件系统范围替换；失败要有记录。
5. 写入后读取实际文件确认结果；返回真实文件变化，不只返回模型文本。

**测试：**未确认不写、拒绝不写、重复确认不重复写、旧文件变化报冲突、越界/符号链接被拒绝、失败不损坏原文件。

```bash
python -m unittest discover -s tests -p "test_write.py" -v
```

**差异声明：**用户确认与受限路径是本学习版增加的保护，不是 Pi 原版内建的完整权限系统。原版默认以启动进程的权限工作。[S2]

### L12 · 实现可解释的 edit

**目标：**学会局部修改，而不是每次重写整份代码。[S10]

**文件：**`agent_tools/edit.py`、`tests/test_edit.py`；复用上课提议与确认机制。

**学习版参数：**`path`、`old_text`、`new_text`。第一版仅接受“旧文本恰好出现一次”的精确替换。

**操作顺序：**

1. 检查路径、文件大小及参数类型，禁止空 `old_text`。
2. 读取文件，统计精确匹配数量。0 次返回未匹配，超过 1 次返回歧义；不要猜位置。
3. 提交替换草稿，展示 diff 与文件旧哈希；批准后执行。
4. 验证无关内容保持不变，换行和编码符合声明的支持范围。
5. 增加测试：唯一匹配、重复匹配、不匹配、旧文件被外部修改、Unicode、最后一行无换行。

**理解问题：**模糊匹配在“更容易成功”和“改错位置”之间有什么取舍？

### L13 · 实现受控 run_tests，不先开放任意命令

**目标：**获取真实退出码、输出、超时与验收结果。[S20][S23]

**文件：**`agent_tools/execution.py`、`tests/test_execution.py`。先对命令构造和容器适配器使用替身测试，再运行隔离集成测试。

**学习版工具：**`run_tests(case_id)`，`case_id` 由预先登记的样例映射到工作区、受保护测试和固定执行参数，模型不能直接传入任意宿主机命令。

**操作顺序：**

1. 先构造参数数组，不拼接由模型控制的宿主 Shell 字符串。
2. 在隔离环境中运行，返回 `exit_code/stdout/stderr/timed_out/truncated/duration_ms`。
3. 对输出设置字节上限，仍继续排空管道，避免子进程因缓冲区满卡住；不要把无限输出先全部保存在内存再截断。
4. 父进程超时必须结束实际工作进程/容器。只杀掉 `docker` 客户端，不保证容器已经停止；使用每次运行的 ID 做明确清理与检查。
5. 不继承包含模型 Key 的完整环境。容器仅获得运行测试必需的变量；Provider 调用留在控制进程，不在待执行代码的环境中。

**Docker 实验的固定约束示意：**

```text
镜像：由人预先准备并记录 digest，包含运行样例所需的 Python 与测试依赖
工作区：本次新副本 → /workspace
验收：受保护测试 → /harness，只读挂载
网络：none
根文件系统：只读
临时目录：有大小上限的 tmpfs
权限：非 root 用户，去掉额外 capability，no-new-privileges
资源：内存/CPU/进程数上限
超时：控制进程能够终止容器并确认清理
```

官方参数包括 `--network none`、`--read-only`、`--cap-drop ALL`、`--security-opt no-new-privileges`、`--user`、`--memory`、`--cpus`、`--pids-limit`、`--tmpfs` 与受控 `--mount`。[S20]

镜像的安装与依赖准备由人显式授权；不要让模型在无网络沙箱失败后自动升级到宿主机执行。容器有剩余风险，不是绝对安全保证。宿主工具权限、挂载与 daemon 安全仍要检查。

**失败测试：**固定任务返回非零；无限等待触发超时；大量输出被截断；非法 case 被拒绝；超时后没有遗留容器；只读测试不能被修改。自己的 Python 测试命令示例：

```bash
python -m unittest discover -s tests -p "test_execution.py" -v
```

**过关：**控制程序能根据实际结果判断测试失败，不能解析到一个 `OK` 字符串就当所有测试通过。

<a id="l14"></a>
### L14 · 串起第一个修复闭环

**目标：**让 Agent 读代码、测试、提出修改、再次测试，最终留下可验证补丁。

**文件：**`agent.py`、`evals/`、`tests/test_coding_flow.py`。

**操作顺序：**

1. 用模拟 Provider 按预设路径走完整流程，验证状态与工具连接；这时不验证模型选对了补丁。
2. 显式真实模式中，让模型读取样例、取得测试失败、提出修改。不要在系统提示中直接塞入正确实现。
3. 用户确认后把补丁应用到本次工作区，再由受控工具运行测试。
4. 测试失败时允许有限次继续；预算不够就停止并交代已修改内容、当前证据和剩余问题。
5. 最终核对源文件 diff、受保护测试哈希和独立验收结果；未运行的检查必须写“未运行”。

**不要固定工具序列充当智能：**同一个任务允许合理的不同查找顺序；正确结果必须来自真实环境变化。

**故障练习：**模型声称修好了但没调用编辑；改错文件；只让已知样例通过；尝试删除失败测试。验收都应能发现。

**阶段成果：**一个受控 Coding Agent，而非完整 Pi。可以继续以 `repo-reader-agent` 为目录名，README 说明新增写入/测试能力即可。

### L15 · 在隔离环境中增加 Pi 风格 bash 工具

**目标：**理解 Pi 默认四个工具中的命令执行能力，而不是把它漏掉或直接在宿主机放开。[S11]

**前置硬条件：**第 13 课的隔离、取消、清理、输出限制已经实测；否则停在补丁草稿，不启用本课。

**操作顺序：**

1. 定义自己的 `bash(command, timeout_seconds)`，固定在本次沙箱 `/workspace` 内调用 Bash；Windows 宿主不等于在宿主 PowerShell 执行模型字符串。
2. 命令字符串是刻意交给容器内 Shell 执行的数据。Python 到 Docker 的控制参数仍使用数组，不能被注入成宿主命令。
3. 不挂载宿主 credentials、整个 home、主项目、Docker socket；默认关闭网络与提权。
4. 输出仍分 stdout/stderr，记录退出码和时间，取消能停止整组进程/容器；长输出存受控位置并返回截断摘要。
5. 默认仍优先提供固定 `run_tests`。开放 bash 的实验需要显式选择执行 profile，不因模型要求就升级权限。

**验收：**容器内正常命令、非零退出、长输出、超时、取消、文件持久化边界；证明模型看不到测试用的假凭据哨兵与未挂载文件。不要拿真实秘密做测试。

**重要区别：**仅做命令白名单但允许执行被模型修改的 Python，仍然可以执行任意代码；真正的边界是受控执行环境，不是命令名字。[S23]

**阶段 C 过关：**读、写、编辑、执行、测试、停止能完整连起来；安全限制如与 Pi 默认行为不同，记录到兼容矩阵，而不是为了外观一致去掉保护。

<a id="l16"></a>
### L16 · 把会话写成追加式记录

**目标：**程序退出后历史不丢失，而且能区分“历史记录”和“下一次模型实际看到的上下文”。[S12]

**文件：**`sessions.py`、`tests/test_sessions.py`。

**建议学习版条目：**`schema_version/id/parent_id/timestamp/type/payload`。自己的文件不写进原版 `~/.pi`，字段不同就不称 Pi JSONL 兼容。

**操作顺序：**

1. 一行一条 JSON，使用 UTF-8 和明确换行；保存用户消息、完整助手消息、工具结果与运行状态。
2. 为每条生成唯一 ID，初期 `parent_id` 总是指向上一条，先形成线性链。
3. 单进程单写入者，写入成功后才更新内存位置；模型流式碎片暂不混成完整消息。
4. 从文件重新读取并验证类型、版本和条目关系。中间坏行拒绝正常恢复；尾部未完整写入可隔离并明确报告，不静默丢弃任意历史。
5. 会话目录不在工具允许范围内；日志也不能包含 Key。原始敏感工具内容的保存要有显式策略。

**测试：**保存/加载等价、Unicode、重复 ID、坏 JSON、错误版本、最后一行部分写入。`runs/` 默认 Git 忽略，但“未提交”不等于“已加密”。

```bash
python -m unittest discover -s tests -p "test_sessions.py" -v
```

<a id="l17"></a>
### L17 · 恢复任务，不自动重复副作用

**目标：**中断之后知道哪些已完成，哪些结果未知。

**文件：**`sessions.py`、`agent.py`、`tests/test_recovery.py`。

**操作顺序：**

1. 新增 `--resume` 或明确的恢复入口，从已保存会话重建上下文；参数名称是学习版约定。
2. 识别未得到结果的工具调用。只读工具可以在明确预算下重试；写入/命令结果未知时标为 `recovery_required`。
3. 对写入提议记录内容哈希、批准记录与操作 ID；只凭模型 call ID 不保证业务幂等，因为重新生成可能换 ID。
4. 遇到“实际写入完成、结果还没落盘就崩溃”，先查现存文件与操作账本，再决定继续，不能无条件重放命令。
5. 恢复前检查工作目录、权限 profile、文件版本与 Provider 是否仍可用。

**三个必须实验的断点：**工具调用前；写入后但结果保存前；最终结果保存后。分别验证不会丢失授权或重复执行。

**消息合法性：**下一次发送模型前必须处理悬空 call/result。不能在历史中留下无法关联的结果，也不能为了凑齐格式伪造成功结果。

**本项目入口：**`agent.py` 的 `recover_agent()` 会重建最近一次运行的 `history`，检查工作区、权限配置和 Provider 客户端类型，并报告 `ready_to_resume`、`completed` 或 `recovery_required`。它本身不会发起模型请求；只有在读取调用悬空、预算大于 0 且工作区/只读权限匹配时，才会重试 `list_files`、`read_file` 或 `search_text`。Provider 检查只确认调用方提供了匹配类型且有 `respond()` 接口，不代表已联网验证服务可用。

```python
from pathlib import Path

from agent import recover_agent
from model_client import MockModelClient
from sessions import SessionStore
from tools import ROOT

recovery = recover_agent(
    SessionStore(Path("runs/session.jsonl")),
    model_client=MockModelClient(),
    workspace_root=ROOT,
    permission_profile="read_only",
    read_only_retry_budget=0,  # 先只检查，不重试读取工具
)
print(recovery["status"], recovery["reason"])
```

`run_coding_flow(..., session_store=store)` 还会把写入提议的相对路径、新旧 SHA-256、独立 `operation_id` 和绑定提议的批准记录到账本；写入结果未保存时，恢复逻辑只比较工作区文件哈希并要求人工决策，不会再次调用编辑器或命令。

**过关：**无副作用重复执行、未知结果诚实暴露。会话恢复不等于能够安全“从任意代码行继续”。

<a id="l18"></a>
### L18 · 会话树、分支与回到历史节点

**目标：**复现 Pi 树状会话的核心思路。[S12]

**文件：**`sessions.py`、`tests/test_branches.py`。

**操作顺序：**

1. 用 `id → entry` 索引和 `parent_id` 表示树，保留活动叶子 ID。
2. 从叶子沿父指针回溯得到活动路径，再逆序构造模型历史；不能把兄弟分支全部拼进去。
3. 从同一个用户节点创建两条后续回答，显示简单文本树。
4. 提供选择活动节点的入口，测试孤儿节点、循环引用和错误节点类型。
5. 分别区分“同一文件中新分支”“复制到新会话”“工作目录文件回退”。

**必须理解：**切换聊天分支不会自动撤销之前真实文件修改。要比较两种修复方案，使用独立工作区或受控版本快照；不要在存在用户未提交改动时自动 `git reset --hard`。

**验收：**给活动分支 A 发请求时，B 的私有内容不混入上下文；原始历史仍保留。

<a id="l19"></a>
### L19 · 上下文构造与项目指令

**目标：**定义每次模型请求实际包含什么，而不是无限追加所有内容。

**文件：**`context.py`、`tests/test_context.py`、必要的资源清单。

**操作顺序：**

1. 实现 `build_context(active_path, instructions, tool_specs, budget)`，输入原始记录，输出一次模型请求用的副本。
2. 分清系统规则、用户目标、资料、工具结果；资料中的指令不能自动升级为授权。
3. 指令来源先限定到人显式允许的练习文件，显示加载了哪些文件和哈希。以后再对照 Pi 的目录发现/覆盖行为。[S7]
4. 留出响应预算，限制工具结果大小，优先保留当前任务约束和完整调用/结果组。
5. 对同一记录分别生成“大预算”和“小预算”上下文，验证关键要求没有丢失；超限不能静默切掉半个调用。

**特别分清两份 AGENTS：**学习仓库给 Codex 助教的 `AGENTS.md` 与被分析仓库里可能存在的 `AGENTS.md` 不是同一种信任来源。后者只在你明确授权将它作为项目指令时加载；不让被检索文本重写执行权限。

**过关：**能解释“保存了这些历史”与“本次发送了哪些历史”的差别。不要把状态持久化等同于永远把所有历史塞给模型。

<a id="l20"></a>
### L20 · 手动压缩，再做自动压缩

**目标：**长会话可继续，同时不把摘要当作无损记忆。[S13]

**文件：**`context.py`、`sessions.py`、`tests/test_compaction.py`。

**操作顺序：**

1. 先用固定摘要器测控制流程；选择完整轮次边界，保留原始记录，仅为后续请求生成摘要＋近期记录。
2. 摘要字段由你规定：目标、限制、已完成事实、未完成事项、失败、关键文件、下一步。
3. 保持工具调用和结果成组；一轮太大时第一版明确停止或回退，不随意从工具结果中间切断。
4. 用户显式开启真实摘要器后，记录摘要模型、请求、用量与失败情况；失败时不能先删旧上下文。
5. 再增加阈值触发：用所选模型对应的 Token 计数或可信用量信息。字符数只能作为保守近似，不能声称精确 Token。
6. 同一任务在未压缩/压缩后运行对照，检查“不能修改测试”等约束仍被程序强制执行，不能只依赖摘要记住。

**边界测试：**连续两次压缩、摘要丢掉限制、超长单次工具输出、摘要超时、分支切换后压缩。完整历史仍可追溯，摘要没有把未运行检查改写为“已通过”。

**差异：**Pi 支持更细的自动压缩和分支摘要；这一课是可验证子集，完整匹配需要后续边界测试，不混称已经逐项兼容。

<a id="l21"></a>
### L21 · 流式输出与异步基础

**目标：**让用户看到逐步到达的输出，同时不执行尚未收完的工具参数。

**文件：**`model_client.py`、`events.py`、`tests/test_streaming.py`；有必要时拆分 Provider 包。

**先补的语法只有本课所需：**迭代器、生成器、`async/await` 与取消。看一个“分三次返回文本”的小例子，再接真实 SDK；不要先完整学习异步框架。

**操作顺序：**

1. 用模拟流发出开始、文本片段、结束事件，UI 订阅后逐步显示。
2. 工具参数片段按各自 call ID/位置累积；交错的两个调用不能串在一起。
3. 收到整条助手消息的正常结束之后，检查所有参数和停止原因，再执行工具。
4. 如果输出长度截断，即便抢救出的 JSON 能解析，也不当作完整工具请求执行；返回明确的未执行/失败状态。[S6]
5. 接真实 SDK 流，保留 SDK 要求的协议项与用量。不要为了显示“思考过程”要求模型泄露内部推理；可观察事件已足够调试。
6. 取消/断网后不追加重复完整消息、不继续执行残留工具；重试计数包含实际尝试。

**验收：**半个 JSON 不执行、两工具片段不串线、重复终止不重复调用、取消没有后续工具副作用。

<a id="l22"></a>
### L22 · Steering 与 Follow-up 队列

**目标：**在任务运行中接受用户新指令，而不打乱协议。[S6][S7]

**文件：**`agent.py`、`ui.py` 或输入队列适配器、`tests/test_queue.py`。

**本计划对照的含义：**Steering 在合适的下一轮边界介入当前任务；Follow-up 在当前工作自然结束后继续。它们不同于取消。

**操作顺序：**

1. 先用模拟器在工具执行时注入消息，不先做复杂键盘界面。
2. 缓存消息，当前完整工具批次结束、消息关联合法之后，再将 Steering 加入下一次模型上下文。
3. 当前循环将结束时检查 Follow-up；有待办且预算允许才开下一轮，避免无限外层循环。
4. 明确队列一次处理一条还是批量；顺序固定可测试，未处理消息不会静默消失。
5. 加上取消：停止当前运行，将未消费消息明确返回用户；不得重放已经执行的命令来“恢复屏幕”。

**测试：**长工具期间输入新消息；同时排队两条；最后一轮前到达的新消息；预算耗尽；取消时还有待办。教学版先串行工具，再研究原版的并行执行选项。

**阶段 D 过关：**长会话不只“能继续聊”，而是可以保存、恢复、分支、压缩和受控插入指令。

### L23 · Skills 和 Prompt Templates

**目标：**区分“任务方法”“可执行工具”和“模型本身”，按需加载资料。[S14]

### L24 · 事件 Hooks 与可插拔扩展

**目标：**给系统增加能力时，不用修改循环主体。[S15]

**文件：**`extensions.py`、一份由自己编写的本地 Python 扩展、`tests/test_extensions.py`。

**自己的最小扩展接口：**注册工具、订阅事件、在工具执行前返回允许/阻止结果。接口命名由你定义并写入说明，不冒充 Pi ExtensionAPI。

**操作顺序：**

1. 先用普通函数表订阅 `tool_started` 和 `tool_finished`，打印计数；事件回调异常不能被吞掉后继续敏感操作。
2. 在校验后、执行前增加 `before_tool` 检查点；拒绝时返回结构化错误并记录原因。
3. 写一个“禁止编辑验收测试文件”的本地扩展做演示，但底层 policy 同样禁止，不能把安全性全押在可卸载插件上。
4. 允许添加一个新的纯只读工具，不更改 `agent.py`；重复工具名默认报错，不悄悄覆盖。
5. 只加载人显式选择并检查过的本地扩展；不从被分析仓库自动 `import` 代码。

**信任边界：**Pi 的原生扩展是执行代码，不是无害文档。Python 插件同样有进程权限；一个小 Hook 并不形成完整沙箱。[S15]

**过关：**新增扩展不改核心循环，失败有明确行为，未信任代码不会因文件存在而自动执行。

### L25 · 终端交互与 TUI

**目标：**同一执行核心既能打印，也能驱动交互界面。[S25]

**文件：**`ui.py`、`main.py`、`tests/test_ui_state.py`。

**操作顺序：**

1. 先做普通 REPL：输入问题、输出答案、输入退出命令；不要一开始造终端渲染库。
2. 界面订阅事件，展示当前工具、进度、结束状态与未验收提醒。UI 不直接调用文件写入绕开循环。
3. 加 `/new`、`/resume`、`/compact` 等你已实现能力的命令；未实现功能不能仅放按钮伪装可用。
4. 再按需要使用成熟 Python 终端库，明确记录所用版本。布局可以简单，目标是输入、取消和输出不互相覆盖。
5. 测试中文、宽字符、多行输入、长工具输出、窗口变化、取消与恢复后的显示；手工观察与自动状态测试分开记录。

**差异声明：**使用现成 Python 终端库属于 UI 能力实现，不等于重写 `pi-tui` 的差分渲染引擎。要原生渲染兼容，在第 29 课单独列项目。

**过关：**去掉 TUI，核心测试仍可运行；用终端也能完成从问题到修复结果的流程。

<a id="l26"></a>
### L26 · JSONL / RPC 与可调用接口

**目标：**让另一个程序使用你的 Agent，不必解析漂亮的终端文字。[S16][S24]

**文件：**`rpc.py`、一个最小客户端、`tests/test_rpc.py`。

**先定义自己的协议：**例如请求带 `id/type/payload`，响应带 `request_id/type/payload`。初始命令只做 `prompt`、`get_state`、`abort`，先保持清楚，不声明兼容 Pi 原生协议。

**操作顺序：**

1. 一条 JSON 对应一条由 LF 分隔的记录；stdout 只输出协议记录，人类调试日志放 stderr。
2. 读取字节流时按 `b"\n"` 分隔，不能用会把 U+2028 等 Unicode 分隔符也当换行的泛化 `splitlines()` 拆协议。发送端让嵌入的换行由 JSON 编码处理。
3. 请求返回与持续事件关联正确 ID；明确“已接受请求”和“任务完成”不是同一消息。
4. 运行时必须继续接收输入才能处理 abort：采用受控输入线程/异步任务，输出集中到一个序列化通道，防止多线程 JSON 交错。
5. EOF、损坏 JSON、未知命令、重复 ID、忙碌时再次 prompt，都有约定错误/排队规则。
6. 提供简单 Python 函数接口复用同一核心；不要让 CLI、RPC、SDK 各自复制一个循环。

**验收：**父进程发起一个任务，收到工具事件，在运行中取消，收最终取消状态；长中文文本含特殊分隔符也不拆坏记录。未运行模型时可用 Mock 完成全部协议测试。

**对照边界：**Pi 的 RPC 和自己的 RPC 都叫 JSONL，不代表字段兼容；第 29 课再做适配和差分测试。

**阶段 E 过关：**具备可复用方法、受控扩展、终端交互与程序接口的学习版 Coding Agent。

### L27 · 只补必要 TypeScript，运行原版一个局部测试

<a id="l28"></a>
### L28 · 写一个真正由 Pi 加载的 TypeScript 扩展

**目标：**证明能使用原生扩展点，不再只做行为类比。[S15]

**独立练习目录：**在原生练习目录中新增一个 `extensions/learning-stats.ts`，不修改 `pi-reference` 内核，也不把它放进自己的 Python 自动加载目录。

**操作顺序：**

1. 参考固定版本 `docs/extensions.md`，定义导出工厂函数与 `ExtensionAPI` 类型；按本次版本使用实际可用的导入，不照搬旧博客。
2. 第一版只订阅工具事件，统计工具调用次数，输出到受控 stderr/界面，不创建新命令执行能力。
3. 用 `-e` 显式加载这一个文件，关闭未知扩展自动发现；先验证加载，再显式授权一条只读模型任务观察事件。
4. 接着注册一个纯函数只读工具，如返回练习材料目录的非敏感摘要；输入校验和错误必须具备。
5. 再使用原版 Hook 阻止一个明确不允许的写入场景，检查被阻止时的真实行为；这仍不能替代 OS 沙箱。

**关键区别：**这一个 TS 文件可以被固定版本 Pi 真实加载，才叫 Pi 原生扩展；之前的 Python Hooks 不是原生扩展。

**过关：**保留扩展源码、加载命令、版本和真实/模拟验证范围；不需要把它立即发布到 npm。

<a id="l29"></a>
### L29 · 能力差分与“全量复现”矩阵

**目标：**看清哪些已经相似，哪些没有兼容，不靠截图判断。[S7][S16]

**文件：**`docs/COMPATIBILITY.md`、`evals/` 中的对照任务和结果。

**操作顺序：**

1. 在相同人工夹具上设计可观察合同，例如“读取范围准确”“精确编辑歧义时如何处理”“恢复后不丢结果”。
2. 对确定性机制使用固定输入和替身，比较输出结构、错误、状态、文件变化；不比较模型自然语言逐字一致。
3. 对任务效果尽量固定模型、上下文、工具政策和预算；差异无法控制时报告，不能把它算成实现优劣。
4. 原版和学习版使用不同的干净工作副本、独立会话目录。会话树分支不自动回滚文件。
5. 每项记录 `未做 / 子集已验证 / 已兼容固定合同 / 不适用`、证据与已知差异。不要只有绿色勾，没有测试范围。

#### 全量对齐需要另行完成的事项

| 能力组 | 主线已覆盖 | 真正原版对齐还要做什么 |
| --- | --- | --- |
| 模型适配 | 一家 Provider、完整消息与错误处理 | 逐个声明支持的 Provider、认证方式、模型能力、原生必需字段、限流与流式差异；不能只改 base URL |
| 内容类型 | 文本与工具调用 | 图片等内容块、协议保留项、上传约束；未支持类型明确拒绝 |
| 工具 | 受控 read/write/edit/bash 与辅助搜索 | 原版参数默认值、截断、模糊匹配、跨平台 Shell、输出语义；安全增强保留并标明差异 |
| Agent 核心 | 循环、串行、错误、取消、队列 | 并行工具、Hook 顺序、轮次准备、终止批次等可观察合同；写冲突不得随意并行 |
| 会话 | 追加日志、恢复、树、分支 | 原版版本化 Schema、导入导出、标签、迁移、损坏处理；自己的 JSONL 不直接交给 Pi 读取 |
| 压缩 | 手动/自动摘要的受控子集 | 原版分割轮次与分支摘要的边界、相关用量与事件；不能破坏协议保留项 |
| 资源 | Skill、模板与本地显式加载 | 原版目录优先级、元数据规范、包安装/更新/卸载、冲突和信任规则 |
| 扩展 | Python 本地 Hooks＋一个原生 TS 扩展 | 要运行任意 Pi TS 扩展，必须使用兼容的 TS 运行时/API 或移植；不是 Python import 能替代 |
| 终端 | 可用的 Python 交互界面 | pi-tui 的输入、布局、差分渲染、终端能力和平台测试；依赖成熟 UI 库的部分要如实注明 |
| 程序接口 | 自己的 RPC 与 Python 函数 | 原版 RPC 字段、事件时序、取消和错误；SDK 导出与类型是另一项合同 |
| 配置/安全 | 学习版 policy、独立路径 | 原版项目信任、资源加载和设置优先级；信任项目不等于命令安全沙箱 |
| 工程基础设施 | 自己的可复现环境 | 原版构建、依赖锁、发行与各平台资产；不必学习初期就重写 |
| 新/实验性模块 | 仅定位，不纳入初期实现 | 固定版本的 Chord、Telemetry、session backend、protocol/client/server 各自按 README、package scripts 与测试做独立子计划 |

原版开发文档将远程 server/client 标为开发期实验功能，与本地 SDK/stdio RPC 的定位不同。不要把实验性服务器当作完成第一个本地 Agent 的强制依赖。[S18]

#### 需要原生 TypeScript 完整分支时怎么走

不是同时另开第二个学习主线。完成上面的 Python 机制之后，按以下顺序逐项替换/移植，复用相同外部合同测试：

1. 类型与 Provider 边界；先使用官方 `pi-ai` 也可以，但应注明“依赖原版模型层”，而不是声称自己实现了该层。
2. 自己的 TS 工具与循环；模拟测试先过，再做明确授权的真实测试。
3. 会话、上下文、事件、扩展接口；每次只迁移一个职责，保持对照输出。
4. 原生 TUI / RPC / SDK 与资源发现；明确复用官方库还是独立实现。
5. 所需平台、Provider 和格式兼容矩阵逐项通过后，再发布与固定版本的兼容声明。

如果选择直接 Fork 原版做改造，应标为“基于 Pi 的二次开发”；如果依赖原版 Agent 核心，应标为“基于 Pi SDK 的应用”。这两者有价值，但与从零实现循环不同。

### L30 · 交付、评测、复盘与回流主项目

**最小交付：**

- `docs/SOURCE_MAP.md`：固定版本与源码对应关系。

3. 明确授权后对固定任务集运行真实评测；记录模型、Prompt、代码、输入夹具版本、尝试次数、时间、用量和任务结果。
4. 对照固定工作流与动态循环，比较必要的任务结果而非宣传“越多轮越智能”。
5. 添加改变需求的练习：自己接入一个新只读工具；不复制完整答案重建简化循环；解释一个中断恢复案例。

## 十、统一测试策略：不让测试拖垮学习

### 10.1 三层验证，默认不收费

早期使用 Python 标准库 `unittest` 组织用例和断言；测试发现命令只在对应测试文件已经存在后使用。[S22]

| 层 | 内容 | 什么时候运行 | 不能据此宣称什么 |
| --- | --- | --- | --- |
| 快速层 | 参数、文件、分发、Mock 循环、上下文、事件 | 改相应逻辑时 | 真实模型一定完成任务 |
| 隔离集成层 | 测试执行、写入、取消、进程清理、恢复 | 改相关模块或阶段验收 | 所有生产环境都安全 |
| 真实模型层 | 指定任务、证据与业务结果 | 显式允许真实调用、关键模型/Prompt/工具改动后 | 少量成功即证明普遍可靠 |

测试名称和记录至少注明：`mode`、`executed`、`passed/failed/skipped`。预期结果写在规格里，实际结果写在运行记录里，不互相替代。

先用 12 个主要任务形成基线，再按失败增长到约 20—30 个；数量是练习建议，不是能力认证。开发样例与留出验收样例分开，不能看到失败就只修改评分标准。

### 10.2 第一批 12 个验收任务

| 编号 | 场景 | 必须检查的事实 |
| --- | --- | --- |
| E01 | 读取已知说明 | 答案引用真实取得的行 |
| E02 | 跨两个文件查找 | 实际取得必要证据，不固定唯一调用顺序 |
| E03 | 资料没有答案 | 明确不足，不虚构依据 |
| E04 | 无法读取文件 | 错误返回可观察，未泄露路径/秘密 |
| E05 | 恶意路径与符号链接 | 无越界读取/写入 |
| E06 | 错误工具名与参数 | 未执行不应执行的函数 |
| E07 | 循环无法完成 | 达到预算停止，不假装成功 |
| E08 | 不完整流式工具参数 | 没有执行部分写入或命令 |
| E09 | 一个小缺陷修复 | 实际文件和独立验收都正确 |
| E10 | 中断后恢复 | 不重复写入/执行未知副作用 |
| E11 | 分支和压缩 | 当前分支与关键约束保持正确 |
| E12 | 用户取消 | 不再开始新行动，执行环境被清理 |

### 10.3 每次修改后的固定动作

```text
说明本次要修的问题
→ 选择能够暴露问题的最小测试
→ 观察失败
→ 只改相关实现
→ 重跑该测试和受影响的邻近测试
→ 查看 diff
→ 记录证据
```

不要让 Coding Agent 反复开启多个大规模测试进程，也不要因为“测试很多”就取消核心安全/恢复检查。影响范围越大，验收范围才相应扩大。

### 11.2 每次交流的顺序

1. 用一句话说明这次只完成哪个可运行的小目标。
2. 解释一个相关概念，不连续抛出十个术语。

7. 记录本次实际结果，再决定下一小步。

`PROGRESS.md` 固定在根目录。本包提供初始化模板；已有实际记录时合并保留，不重置。它没有自动执行权限，授权记录必须对应用户的实际请求。

```text

当前小步：先处理当前实现与统一状态契约的真实缺口

下一小步：一次只补一个可运行能力
真实模型调用：未启用，除非用户明确授权
模型写文件 / 执行代码：未启用
证据：只填实际命令、输出和用户已展示的理解
```

这段是起始模板，不覆盖已存在且有证据的进度。没有测试输出时写“未运行”，不写虚构的绿色通过记录。

## 十二、最常见的卡点和排查顺序

| 现象 | 先检查什么 | 暂时不要做什么 |
| --- | --- | --- |
| Python 没输出 | 文件是否保存、运行的是哪个文件、入口是否调用、返回值是否打印 | 重装全部环境 |
| 无法导入工具 | 同目录是否存在、函数名是否一致、是否出现 tools.py / tools 包冲突 | 随机改变 PYTHONPATH |
| 读取内容不是预期文件 | 实际根目录、允许清单、相对路径和编码 | 开放整个磁盘 |
| 调了工具，模型好像没看结果 | 完整助手调用是否保存、call ID 是否对应、下一次请求历史 | 盲目加长 Prompt |
| 一直在调工具 | 停止条件、预算是否在调用前检查、错误是否形成重复模式 | 无限提高预算 |
| 工具参数看似 JSON 但执行失败 | 类型/字段、输出是否截断、协议是否混用 | eval 模型文本 |
| 已写文件却显示失败 | 写入与结果持久化的先后、操作日志、旧/新哈希 | 自动再执行同一命令 |
| 测试超时后电脑仍在跑 | 实际子进程/容器是否结束 | 只终止 Docker 客户端 |
| 切换会话分支但文件没回退 | 会话树和文件系统是两种状态 | 对主仓库 reset --hard |
| 压缩后忘了限制 | 原始约束是否程序化保存、摘要是否核对、调用组是否完整 | 宣称摘要永不丢信息 |
| 原版 npm 构建失败 | 固定 commit、Node 版本、脚本、依赖锁与网络 | 自动换主分支或禁 SSL |
| RPC 客户端解析失败 | stdout 是否混了 print、是否按 LF 分帧、ID 是否对应 | 直接解析终端彩色输出 |
